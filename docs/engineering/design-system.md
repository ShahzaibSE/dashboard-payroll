# PayrollOps design system

Project-owned. Tokens live in `src/styles/index.css`; this file records the decisions behind them.

## Direction

A dense, calm internal operations tool, not a marketing site. Style family: "data-dense dashboard" (from the UI/UX guidance consulted during design): restrained blue and amber on a cool off-white surface, small type, tight spacing, tables and lists before charts. One memorable element per screen at most; everything else stays quiet.

The guidance's landing-page pattern recommendation does not apply to this product and was not used.

## Tokens

All colours are CSS variables on `:root`, mapped into Tailwind with `@theme inline`. Names follow shadcn conventions (`background`, `foreground`, `card`, `muted`, `border`, `primary`, `ring`, ...) plus project tokens for the sidebar, status tones and chart series.

- Light theme only (`color-scheme: light`). Dark mode is deferred; the token layer is structured so a `.dark` or media-query override can be added without touching components.
- Radius 6px (`--radius`), borders 1px, no decorative shadows or gradients.

### Contrast (WCAG 2.2 AA), checked with a script against the token values

| Pair | Ratio | Requirement |
|------|-------|-------------|
| foreground on background / card | 16.8 / 17.9 | 4.5 |
| muted-foreground on background / card / muted | 7.1 / 7.6 / 6.6 | 4.5 |
| primary-foreground on primary | 8.7 | 4.5 |
| accent-foreground on accent | 8.4 | 4.5 |
| sidebar text / muted text on sidebar | 11.3 / 6.4 | 4.5 |
| status text on its tint (success, warning, danger, info, neutral) | 6.4 to 8.4 | 4.5 |
| input border on card | 4.8 | 3 (non-text) |
| focus ring on page background | 8.2 | 3 (non-text) |
| chart series on card (APAC / EMEA) | 8.7 / 3.7 | 3 (non-text) |

Sidebar links use a white focus outline (16.7 against the sidebar) because the default ring is too dark there.

## Typography

System UI font stack (`font-sans`), no web fonts: the app makes no external requests, so there is no font CDN and no font package. Numbers use tabular figures (`tabular` utility) so columns of money and counts align. Base size is 15px; page title 20px semibold; card and section titles 14px semibold; table and body text 14px or smaller; metadata 12px.

## Density and layout

- Content max width 88rem, page padding 16px (mobile) and 32px (desktop).
- Cards use 16px padding and 12 to 16px gaps. Prefer lists and tables over decorative tiles.
- Breakpoint that matters: `lg` (1024px). At or above it the navigation is a fixed 15rem sidebar. Below it the navigation is a drawer opened from a Menu button in the header.
- Nothing may cause horizontal page scroll at 360px and up; wide tables scroll inside their own container.

## Status and meaning

Status is always conveyed by text plus an icon, never by colour alone. Tones: `success`, `warning`, `danger`, `info`, `neutral`, each a foreground on a tinted background. The `Badge` primitive carries the tone; each domain maps its own statuses to a label, icon, and tone.

Simulation is disclosed permanently in the header: "Simulated – changes are local and not saved", with the fixed data date.

## Charts

Recharts, with the series colours `--chart-apac` and `--chart-emea`. Every chart has direct value labels and a screen-reader data table with the same values, including the region. The two region hues differ in lightness, and the legend names each region with its total, but the bars themselves carry no non-colour region marker; the table is the non-colour source. Prefer a sorted bar chart for category comparison; use a list or table when the chart would not add meaning.

## Components and the shadcn decision

Primitives live in `src/components/ui/`: `Button`, `Badge`, `Card`. They are hand-written in the shadcn style (`cva` variants, the `cn` helper, shadcn token names) and are not generated by the shadcn CLI.

Reason: the current shadcn registry installs `radix-ui`, the `shadcn` package, `tw-animate-css`, a third-party `cn` package and a font package, plus a default component set, for primitives that need only a few lines of accessible markup here. The only direct UI dependencies added for M4 are `class-variance-authority` and `lucide-react`. `components.json` is kept, so the CLI can still be used later (for example to add a dialog or menu) as a deliberate, reviewed dependency decision.

The mobile drawer is a disclosure pattern, not a modal: `aria-expanded` on the Menu button, one `nav` landmark that is removed from the layout when closed, Escape closes it and returns focus to the button, and any navigation closes it.
